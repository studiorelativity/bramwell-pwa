## 2. Rulings to promote at gate close

Into `DECISIONS.md` unless marked otherwise.

1. **The auth gate.** One token request per signed-out session. Writes are
   deliberately ungated — a Save press *is* the gesture a popup needs, and the
   user must learn the write failed. **Any** successful token acquisition clears
   the gate, including one obtained on the write path: without that, a
   successful save left background month loading suppressed forever while the
   UI showed "connected".
2. **`sw.js` is emitted by `scripts/build-sw.mjs` (esbuild, IIFE), not by
   `vite.config.ts`.** This **supersedes** the in-force line in `DECISIONS.md`
   "shell and chrome". New reason: Vite's ESM output cannot produce a classic
   worker, and `CONVENTIONS.md`'s static SW check requires one. `SPEC.md`'s file
   layout has been updated to name the script (commit `5e4c019`).
3. **`window.bramwell` survives as a DEV-only test seam**; `#devbar` and the
   `#harness-*` buttons are deleted. This **amends** the stage-04 carry-forward,
   which said to delete both: `scripts/shot.mjs` reads the seam and has no other
   way in. It now carries `ctl`, `day`, `chrome`, `addHere`.
4. **`warmCache` counts `loading`/`error` months that still hold events**, not
   `ready` alone. A warm start loads months as `ready` and then flips them to
   `loading`/`error` as the stale-token refresh fails; counting only `ready`
   would flash first-run over a warm cache on every launch.
5. **`#app` reserves `--fab-inset`** rather than floating the FAB, so the Sunday
   clearance is structural rather than measured-and-hoped. It costs a strip of
   calendar on desktop too. This shifted the stage-04 geometry baselines down
   10–12px at all three viewports; the harness expectations were **not** adjusted
   to match, and the before/after is recorded in the task report.
6. **Sign-out returns to first-run via intent, not by clearing the cache.**
   A non-persisted `leftDeliberately` flag outranks `warmCache()`. SPEC's "the
   first-run screen never covers a warm cache" is about stale *auth*, not about a
   user who chose to leave. **Consequence to accept:** a later reload with a warm
   cache returns to `stale` plus the pill, because the cache really is warm and
   the grant really was revoked.
7. **`RECONNECT_GRACE_MS` is a timing constant that is neither a CSS motion value
   nor scroll physics.** `CONVENTIONS.md` "Style" names only those two homes and
   says "no third home". → **propose a `CONVENTIONS.md` amendment** naming a third
   category: constants that decide *when a UI state is entered*.

## 3. Limits of the evidence — read before citing anything above

- **The harness runs permanently signed out over a seeded warm cache**, so it
  only ever reaches the `stale` state. `#avatar` and the connected state were
  never exercised by a probe; `#reconnect` is *reported*, not asserted, because
  virtual time makes an absence assertion flaky.
- **The `heldRepaint` probe cannot isolate the sheet from the day form.** The
  only way to fire a real `state.ts` cache change without a test-only hook is the
  day form's Save, and `save()` leaves the form open on failure — so both
  conditions of the `||` are true when the gate is read. It proves the OR-gate
  holds. **It does not prove the sheet alone holds the repaint.**
- **`SHEET_SURVIVES` is structural only** — it proves `invalidate()` does not tear
  the sheet down, not that the repaint was held.
- **Headless Chrome's mobile emulation silently widens `innerWidth` to absorb
  horizontal overflow.** This hid the Reconnect-pill overflow bug entirely at a
  390×844 device-metrics viewport — the broken CSS passed its own hit test there.
  The bug was only visible at a desktop viewport. Any future overflow check must
  run desktop-first, or it is measuring the emulator's auto-fit rather than the
  layout. → **candidate for `CONVENTIONS.md` "Verification".**
- **A probe's `hit` value of `""`** — an element with neither class nor id — is a
  red flag, not noise. That value was the visible tell that the FAB-clearance
  probe was measuring a viewport an earlier probe's input focus had drifted
  (844 → 951). It was read as noise on the first pass and reported a clean gate
  row that proved nothing.

## 4. Not tested, and staying open

Carried into `OPEN.md`:

- **60fps on a mid phone** (stage-04 gate row 2, and this stage's carried row) —
  needs the deployed origin. The refetch loop that blocked the stage-04 attempt
  is now contained, so the measurement is unblocked, but it has not been made.
- **`grid-template-columns` interpolation on iOS Safari** — still untested on any
  Safari engine.
- **Everything the SW does at runtime** — registration, offline open, a deploy
  reaching an installed client. Verified statically only; `CONVENTIONS.md` says
  headless Chrome hangs on SW registration.
- **Read-only while stale is enforced only on the FAB and `n`.** The day panel's
  `+ Add` button and its event rows stay editable, and a Save from there will
  fail after the user has typed a whole event. Making them read-only means
  editing `day.ts`, outside this stage's Outputs. **Deliberate scope limit, not
  an oversight.**
- **The settings sheet has no exit transition.** An exit animation needs a
  `transitionend` handshake before removal, and the sheet is rebuilt on every
  open — the handshake would reopen an `isSheetOpen()` correctness window and
  hold `main.ts`'s repaint through the fade. Declined deliberately.
- **`warmCache` reads a genuinely-empty cached month as cold**, so a user parked
  on a wholly empty stretch would see first-run over a warm cache.
- **`addHere()` from the year view swallows `scheduleRemeasure`'s animate flag**,
  so the day snaps open unanimated. This makes one path of the *already-open*
  `remeasure` re-entry race (b) deterministic rather than intermittent. Stage 05
  did not otherwise touch that path. `OPEN.md` says the race should be fixed as
  one deliberate piece of work, not a drive-by.
- **The single `bramwell` SW cache accumulates superseded hashed assets** across
  deploys. This is what makes "a coherent old build offline" work, so it is a
  trade, not a bug — but storage grows without bound.
- Deferred minors: `chrome.ts` re-derives the fallback name instead of calling
  `categories.fallback().name`; `mintName`'s negative-slice edge (unreachable at
  a ceiling of 11); control `aria-label`s go stale after a label-only edit;
  sign-out calls `syncConnection()` twice.
- **Still open from earlier stages, untouched:** `npm run shot` asserting on
  failure; a browser test layer for the three untested write-path fixes
  (`formGen`, the notes sentinel, `eventsOn` ordering); GIS response ordering.

**The one failure.** `_headers` sets `/sw.js` to `no-cache`, and
`bramwell-pwa.pages.dev` serves exactly that. The proxied `bramwell.no.fail`
serves `max-age=14400` instead: the zone's Browser Cache TTL default of 4 hours
overrides any origin TTL lower than itself. `/assets/*` survived only because
its `max-age=31536000` is *higher*. So the rule that matters most is the only
one silently rewritten, and the `_headers` file is not at fault.

Fix at the zone: a Cache Rule scoped to `bramwell.no.fail/sw.js` with Browser
TTL "Respect origin" — narrower than flipping the whole zone, since the apex is
an unrelated site. Recorded in `SPEC.md` DEPLOY and `OPEN.md`.

Gate row 10 ("a second deploy reaches the installed client, no cache bump") must
be run **after** that fix, not before, and must be observed rather than reasoned
about: browsers default `updateViaCache: 'imports'` and cap SW script caching at
24h, so the deploy probably still lands today — but "probably" is not what that
row asks.

## 5b. Found on the deployed app, fixed 2026-08-30

The human opened a day on `bramwell.no.fail` and saw every event twice. One
cause, three reported symptoms:

`render.ts` paints the collapsed read-out into every cell on every fill, and
`main.ts` appends the panel into that same cell without standing it down.
`.chips` and `.more` are positioned against the cell's **bottom**, so a cell
grown to fit the panel pins them on top of the list — each event appeared once
as a `.dp-ev` pill and once as a bare chip, with `+ Add` caught among them.
`.bars` and `.rule` are later siblings inside `.week` at `z-index: auto`, so an
all-day bar also drew a stripe across the panel's header — not yet reported, but
one 72h event away from being.

**Two of the three reported symptoms were consequences, and are recorded as
such rather than "fixed":** the row was always growing correctly
(`panelOverflowsCell: false` at 3 events and at 10, both viewports), and `+ Add`
was already the panel's last child. Only the duplicate was real.

Fixed in `style.css` under `.day[data-open]`: `.chips`/`.more` to `display:
none`, and `z-index: 1` on the open cell so it covers the row overlay crossing
it while the six collapsed neighbours keep their own bar segments.

Regression probe `dayOpenSingleReadout`, on its own fresh navigation (the
`probeFabClears` pattern — in the per-row loop it reported "nothing open" on six
rows of nine while still exiting 0). All three viewports:

```
ok true · openedDay 20677 · chipsHidden true · moreHidden true
dpEvCount 2 · addIsLastChild true · addReachable true · addHit "dp-add"
barAbovePanel false · barAbovePanel_fixOff TRUE
```

That last pair is the point: the probe re-takes the reading with the fix toggled
off and gets `true`, so it demonstrably can fail. A rectangle-intersection test
could not — the bar spans the column either way — and would have passed on the
broken build. Both rules are now in `CONVENTIONS.md`.

## 6. What review caught that testing did not

Eight defects reached the tree and were caught by review rather than by a
passing test. Six originated in the plan, not in execution:

- A failed Connect toasted **underneath** the opaque first-run screen
  (`#toasts` z-index 10 vs `#firstrun` 20) — invisible, on the most likely
  first-run error path.
- The Reconnect pill overflowed its fixed 28px slot by 49px on **every**
  viewport; its centre was unhittable and the document gained horizontal scroll.
  This is one of only two ways a signed-out phone can recover.
- A successful write-path token never cleared the auth gate, so a successful
  save left month loading dead while the UI said "connected".
- `pendingOpenAdd` leaked when a FAB tap was interrupted by tapping another day,
  arming an add form that would open later on an ordinary tap.
- Closing the settings sheet never released the held background repaint.
- `n` opened an invisible form behind the first-run screen.
- The FAB-clearance gate row was measured against a viewport an earlier probe
  had drifted, and reported a clean pass while proving nothing.
- `.set-scrim` hardcoded a colour literal, breaking the one rule
  `CONVENTIONS.md` makes provable by a single grep.
